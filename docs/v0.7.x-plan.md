# 《v0.7.x 可控性方案》

> 目标：把 FlexClash 从"看得见内核"升级为"**管得住内核**"——类型化整个 mihomo 数据面以消灭静态漂移，并在此基础上交付分流规则的自主编辑能力。
> 前置侦察：本轮已实测 `commands/*.rs` 的返回型签名、`src/types/clash.d.ts` 的规模与依赖面、`package.json` 的测试依赖、`store/queries.rs` 的统计能力、`config/profile.rs` 的 YAML 手术设施、`proxy/` 与 `core/` 的 `cfg(target_os)` 分派现状。所有数字均为实测，非估算。
> 状态：**战略共识已达成，尚未写业务代码。**

---

## 0. 结论速览（TL;DR）

| 项 | 结论 |
|---|---|
| 主线 | 7.1 类型化数据面 → 7.2 规则/路由管理器 → 7.3 流量归因统计（后置） |
| 并行必做 | 引入 Vitest，终结前端 0 测试 |
| 明确暂缓 | 跨平台（macOS / Linux）——成本最高、对现有用户零红利 |
| 排序理由 | **技术债优先于新特性，尤其当这笔债正是那个特性的地基时** |

一句话：**7.1 是债也是地基，7.2 是灵魂，7.3 是锦上添花，跨平台是另一个量级的战役。**

## 2. 债务地图（实测证据）

### 2.1 九个裸奔的 `String` 命令

以下命令声明为 `CmdResult<String>`，mihomo 的 REST 报文**原样当字符串穿过 IPC**：

```
get_mihomo_version      get_mihomo_configs      get_mihomo_proxies
get_mihomo_proxy        get_mihomo_connections  get_mihomo_rules
select_mihomo_proxy     get_mihomo_proxy_delay  get_profile_content
```

### 2.2 262 行零校验的手写镜像

`src/types/clash.d.ts`：**262 行，21 个 `interface` / `type`，被 9 个文件依赖**，且**没有任何东西校验它**。

这正是问题所在：mihomo 是活跃上游、schema 会变，而这一层镜像的漂移不会让任何门禁变红。我们花了整个 v0.6.x 把 IPC 做成 tauri-specta 全类型化，而这 9 个命令绕过了全部成果。

### 2.3 前端零测试

`package.json` 的 devDependencies 里**没有任何测试框架**，`src/` 下 **0 个** `.spec.ts` / `.test.ts`。与 Rust 的 179 个单测形成刺眼对比。

刚落地的一批**纯逻辑**目前全部无测试覆盖：
- `notices.ts` 的 5 秒合并去重（`count` 累加而非新增条目）
- `kernel.ts` 的 `availability` 派生（`probing` 归入 `up` 的那条判断）
- `useKernelDataPump` 的启停调度与 `inFlight` 去重
- 此前的 `hashConnections`、`latency_asc` 排序合流

这些全是纯函数，测起来很便宜——**而我们在一次大重构后没有测它们**。

### 2.4 规则与统计的能力边界

| 能力 | 现状 |
|---|---|
| 规则 | `get_mihomo_rules` 只读；**无任何增删改命令**；`RulesView` 仅搜索 / 类型过滤 |
| 统计 | `store/queries.rs` 仅全局 up/down 分桶（`insert_sample` / `query_history` / `count` / `prune`），**无按节点 / 域名 / 规则归因** |

### 2.5 跨平台的真实水位

- `proxy/` 已建成 `windows.rs` + `unix.rs` + `mod.rs` 的 `cfg` 分派——**系统代理层已抽象**。
- `core/elevate.rs` / `job_object.rs` / `route_guard.rs` / `task_autostart.rs` / `startup.rs` 的非 Windows 分支均为**优雅降级**（no-op 或返回 `Err`，如 `task_autostart::enable` 直接 `Err("silent autostart is Windows-only")`）。
- **关键安全确认：没有任何 `unimplemented!()`**。在 `panic = "abort"` 下那等于在 macOS 上直接杀进程——地基是干净的。
- 真正的工作量在别处：sidecar 需按 target 分别下载、`release.yml` 仅 `runs-on: windows-latest`、TUN 在 macOS 需 utun + 管理员授权、Linux 需 `CAP_NET_ADMIN`、静默自启需为 launchd / systemd 各写一遍。

## 3. 战略共识（本轮达成）

1. **地基先行**：用 Specta / Rust 接管全部数据面类型，消灭静态漂移风险；同时引入 Vitest，终结纯前端 0 测试的窘境。
2. **灵魂注入**：在坚实的类型地基上，借助已有的 YAML Patch 设施，实现分流规则 / 路由的自主编辑。
3. **暂缓跨平台**：它不是"要不要"的问题，是"什么时候"的问题。v0.7 不做，但保持它将来便宜。

### 为什么 7.1 必须在 7.2 之前

想在 UI 上编辑一条规则，你先得有 `Rule` 的类型。先做 7.1 再做 7.2 是顺流；反过来每写一行规则编辑逻辑都要回头补类型，是逆流。

## 4. 执行路线

### 7.1 类型化数据面 + Vitest 基建

**类型化**
- 为 9 个裸 `String` 命令定义 Rust 结构体并 derive `Type` + `Serialize`/`Deserialize`。
- 让 `bindings.ts` 生成这些类型，**删除 `src/types/clash.d.ts`**，逐个迁移 9 个依赖文件。
- 迁移期纪律：**一次一个命令**，每个命令单独提交，保证每个提交都能独立编译并通过门禁。
- 预期风险：mihomo 报文中存在可选 / 异形字段。对策与 v0.6.x 一致——**phase-aware 导出**已开启（`bindings.rs` 明确记录了不调用 `disable_serde_phases()` 的理由），`#[serde(default)]` 字段会被诚实地生成为可选。

**Vitest**
- 引入测试框架并接入 CI 门禁。
- 首批覆盖（纯逻辑，零 DOM 依赖）：notices 合并去重、`availability` 派生、pump 调度、`hashConnections`、延迟排序合流。
- 门禁顺序沿用 v0.6.x：sidecar 拉取 → `cargo fmt --check` → `clippy -D warnings` → `cargo test --lib` → 集成测试 → `export-bindings` + 漂移检查 → `vue-tsc` → **新增 Vitest**。

### 7.2 规则 / 路由管理器

后端地基已经浇好，只欠一层楼：`config/profile.rs` 已有 `patch_and_sanitize_yaml` 与 `toggle_tun_block`，注释中明确 `proxy-groups` / `rules` / `dns` 编辑是"re-stitched on top"。

待建（顺序待 7.1 完成后细化）：
- 规则的增 / 删 / 改 / 排序命令，走 YAML 手术而非整文件覆写；
- 编辑后经 `reload_mihomo_config` 热加载，失败可回滚到上一版已验证 YAML；
- 前端 `RulesView` 从"只读浏览器"升级为编辑器（含规则命中测试入口）。

### 7.3 流量归因统计（后置）

当前仅全局总量。按节点 / 域名归因需要累加策略（连接关闭时结算），而采样点现成：Rust 侧 `core/deadlink.rs` 已在轮询 `/connections`。价值明确，但优先级低于 7.2。

## 5. 明确不做：跨平台（以及替代动作）

**不做 v0.7.x 的理由**：sidecar 矩阵 + CI 矩阵 + 四个子系统的平台实现（TUN、提权、自启、路由清理），是对现有用户**零红利**的最高成本项，会吃掉整个里程碑的预算。

**替代动作（半天工作量）**：做一次**平台抽象审计**——
- 确认新增代码不往 `core/` 里硬塞 Windows API；
- 保持 `cfg` 分派纪律（参考 `proxy/mod.rs` 的写法：平台模块 + 统一分派函数）；
- 非 Windows 分支必须是**优雅降级**，**禁止 `unimplemented!()` / `todo!()`**（`panic = "abort"` 下等于进程自杀）。

这样等真要做跨平台时，它仍然便宜。

## 6. 门禁与提交纪律（沿用 v0.6.x 已验证的做法）

```
# sidecar 必须在任何会编译的 cargo 步骤之前拉取
cargo fmt --all -- --check
cargo clippy --all-targets -- -D warnings
cargo test --lib
cargo test --test profile
cargo run --bin export-bindings --features export-bindings && git diff --exit-code -- src/bindings.ts
npx vue-tsc --noEmit
npm run test            # v0.7.x 新增
```

提交纪律：
- 一个 Conventional Commit 对应一层，每个提交独立编译且门禁全绿；
- `bindings.ts` 必须搭在改变 Rust IPC 面的**同一个提交**里——单独的"重新生成 bindings"提交会让中间提交在漂移检查上失败；
- 改 IPC 面后必须跑 `export-bindings` 并同步提交 `src/bindings.ts`；
- 收尾必对账远端：`git ls-remote origin refs/heads/main`（本环境写不进 `refs/remotes/**`，不能靠 `rev-parse origin/main` 判断）。
